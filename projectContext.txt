EduForge: Complete Project Workflow & Blueprint

============================================================
Part 1: Project Architecture & Directory Structure
============================================================

EduForge is structured as a monorepo containing 4 main components:
1. web: The main public student and instructor portal.
2. admin: The top-level EduForge platform super-admin portal.
3. uni-admin: The dedicated portal for university-level administrators.
4. backend: The Spring Boot Java backend powering all portals.

Part 2: Comprehensive Workflow (Instructor - Student - Admin)
============================================================

EduForge operates seamlessly, transitioning between a standard public environment {"Normal Portal"} and an isolated institutional environment {"University Space"}. Below is the workflow breakdown.

--------------------------------------------------
Section A: The Normal Portal (Public Base Platform)
--------------------------------------------------
This defines the everyday, global functions of the platform.
- Instructors: Once registered, instructors jump straight into a "Waiting Room" pending verification from the general Platform Admin (Tier 1). Upon approval, they unlock the classic studio to construct and publish public courses universally available to the student body globally.
- Students: Regular students can make basic accounts, log in, browse the public platform offerings, track their independent progress loops naturally. They can message general instructors on the site publicly via generic shared tools.

--------------------------------------------------
Section B: Enhancement - The University Space
--------------------------------------------------
EduForge scales higher natively through specific institutional networks titled roughly as the "University Spaces." Students entering registered universities unlock an entirely segmented internal network operating under these structural dynamics:

The Three Tier Structure:
1. Tier 1 - EduForge Platform Admin: Operates the entire system. Focuses on onboarding public Instructors, plus spawning macro University structures (delivering "Join Codes" and logins to the individual Universities).
2. Tier 2 - University Admin Portal: Acts via a distinctly isolated standalone codebase (`uni-admin`). Tier 2 assigns Branches, Sections, maps students, and curates and allocates approved institutional courses via an internal semester pool.
3. Tier 3 - Instructors and Students: Interact actively via their pre-built default web portals, newly granted localized "University Space" tabs if they registered with corresponding recognized Colleges.

Phase 1 - University Foundation & Onboarding: Complete.
Phase 2 - University Courses & Semester Allocation: Complete. Auto-enrollment on allocation now active.
Phase 3 - Chapter Deadlines, Assessments & Real-Time Marks Engine: Complete for the current scope. Attendance score, tests average, live-tests slot, manual project placeholders, late-penalty deductions, weighted final score, and grade calculation are now exposed to students and instructors.
Phase 4 - Live Tests & Synchronous Interactions: Core live test flow now built. Instructors can create/schedule/launch/close/delete timed live tests, scheduled tests now auto-launch/auto-close, students receive websocket start/close notifications plus bell notifications, instructors can inspect per-student live test scores, and average live test score now syncs into the marks sheet breakdown. Live classes are still pending.
Phase 5 - Project Space & GitHub Integration: Pending.
Phase 6 - Final Evaluation, Marks Sheet & Certification: Pending.
